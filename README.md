# TemplateMaker

部屋の内装テンプレートを組み立てるための**サンプル家具セット**を、公開されて
いる 3D アセットから作る。

```bash
uv run templatemaker catalog                      # カタログを引く（90MB）
uv run templatemaker survey                       # 基準をかけた残りを見る
uv run templatemaker select --tier a              # マニフェストを書く
uv run templatemaker fetch catalog/abo.tier-a.json  # GLB を引く
uv run templatemaker notice catalog/abo.tier-a.json # 帰属表記を書く
```

## 何を持ち、何を持たないか

**取得に徹する。GLB を解かない。** 読み込み・ノード変換の畳み込み・材質ごとの
分割・間引き・テクスチャの縮小は [CaptureVisualizer][cv] の `assets.py` が既に
持っている。ここで同じものを書くと、同じ GLB の読み方が 2 つに増える。

そのため外部依存が無い。標準ライブラリだけで動く。

[cv]: https://github.com/24th-garnet/CaptureVisualizer

| | |
|---|---|
| `sources/abo.py` | ABO 固有。カタログ取得・語彙の対応づけ・URL 規約 |
| `category.py` | 品目の語彙。**出どころに依存しない** |
| `select.py` | 取捨選択の基準。純関数だけ |
| `manifest.py` | マニフェストの読み書きと帰属表記 |

## 選定と取得を分ける

`select` は何もダウンロードしない。マニフェストを書くだけで、`fetch` がそれを
読んで実体を引く。

選定は安価で決定的、取得は高価。分けておくと**基準を直して選び直しても再
ダウンロードが起きない**。段階を広げるときもマニフェストの差分として見える。

マニフェストは git に入れ、実体は入れない。同じマニフェストからは誰が引いても
同じ集合になるので、GB 単位のファイルを配らずにセットを共有できる。

適用した基準はマニフェストの `criteria` に埋める。**なぜこの集合なのか**を
集合の外に置かないため——基準を書き換えた後で古いマニフェストを読んでも、何で
選ばれたのかがそのファイルの中で分かる。

## 出どころ

[Amazon Berkeley Objects][abo]。Amazon の実商品 7,953 点の glTF 2.0 が、ASIN
指定で公開 S3 から 1 体ずつ引ける。**ライセンスは 2023 年に CC BY-NC から
CC BY 4.0 へ変わっており、帰属表記だけで商用に使える。**

ブランドは Stone & Beam / Rivet / Ravenna Home / AmazonBasics / Movian と、
ほぼ Amazon のプライベートブランド。第三者デザイナー家具の意匠権が絡まない。

[abo]: https://registry.opendata.aws/amazon-berkeley-objects/

**メッシュは [-1, 1] に正規化され、実寸は root ノードの `scale` が持つ。**
頂点をそのまま読むと全部 1 辺 2m になる。ここでは GLB を解かないので直接の
問題にならないが、受け取る側がノード変換を畳むことを前提にしている。
Tier A の 76 体で `assets.read_glb` の出力をカタログの `extent_x/y/z` と
突き合わせ、**全体が誤差 0.0mm** で一致することを確認してある。

## 取捨選択の基準

全件は 165.6 GB あるが、その大半は要らない。

| | 残り | 取得量 |
|---|---:|---:|
| 全件 | 7,953 | 165.6 GB |
| 品目が決まるもの | 7,113 | 151.6 GB |
| 寸法サニティ（0.02〜3.5m） | 6,280 | 135.2 GB |
| 品目ごとの寸法上限 | 4,053 | 80.3 GB |
| 形状の重複を除去 | 3,416 | 60.2 GB |

**形状の重複**が効く。ABO は同じ家具を色だけ変えて別 ASIN で出すので、頂点数・
面数・寸法が揃うものを 1 体に畳む（最大 11 体が同一形状だった）。

**寸法は品目ごとに上限を持つ。** 一律にしないのは、ソファの 2.1m とミラーの
2.1m が住宅に対して持つ意味がまるで違うため。北米カタログを日本の住宅へ持ち
込むときに効くのはここなので、表は `select.LIMITS` に出してある。

幅は水平の長い方、奥行は短い方として取る。glTF の X/Z のどちらが幅かは書き出し
側の都合で決まり当てにできない。高さだけは Y-up が保証されるので Y を見る。

### 段階

| | 体数 | 取得量 |
|---|---:|---:|
| tier a | 76 | 0.08 GB |
| tier b | 376 | 0.92 GB |
| tier c | 1,336 | 11.2 GB |
| tier d | 3,416 | 60.2 GB |

少ない方から試して、通ったら広げる。ASIN 指定で 1 体ずつ引けるので、後から
足すのにコストがかからない。

品目ごとに切るのは、椅子が 631 体ある一方でベンチが 33 体しか無いため。総数で
切ると椅子だけのセットになる。

## カタログの語彙を信じない

`product_type` は 98 種あるが、形と合わないものがある。

**混ざっているもの**は商品名で解き直す。`HOME_FURNITURE_AND_DECOR`（549 体）は
ソファ・オットマン・ラグ・収納が同居し、`HOME`（176 体）はほぼ壁掛けアートと
ミラー。数が多いので捨てられず、1 つの品目へ寄せると配置の既定値が壊れる。

**形と合わないもの**は寸法で直す。`HEADBOARD`（206 体）は 195 体がベッドごと
で、壁付けの板は 11 体しかない。品目は置き方を決めるので、語彙をそのまま信じる
とベッドが壁に貼り付く。

なお ABO の平たいヘッドボードはほぼ北米の king / queen 幅で、日本の寸法を通る
のは 1 体だけ。この品目は別の出どころから採るしかない。

素材は CC BY 4.0。**同梱して配るなら帰属表記が要る。** `notice` がマニフェスト
